# Preferences

> **The bullets are mine; everything else here is regenerated.** `oculus docs`
> re-renders this guidance and carries the bullets across, so the instructions
> cannot go stale under what I wrote. An empty section below means "not stated
> yet", not "no preference" — and prose under a heading, rather than a bullet,
> stops the merge and is left alone.

Standing preferences that hold across every subject. Subject-specific ones
belong in that course's `agents/INSTRUCTIONS.md`.

One bullet per preference, under its heading, written as an instruction —
"lead with the verdict, then the evidence". Anything true of me that is not an
instruction is a memory, not a line here.

**A preference earns its line the second time.** The first time I say how I
want something, write it as a memory of type `feedback` — with the **Why:**
and **How to apply:** that type carries — and leave this file alone. When it
comes up again, promote it:

```bash
oculus memory promote <name> --section working --as "Lead with the verdict, then the evidence."
```

which adds the bullet here and clears the memory away. Saying "wait until it
has been said twice" only works if the first time was written down; if nothing
was, every time is the first time. Something I state outright as a rule skips
the wait.

This file is opened at the top of every conversation, before anything is
written for me, so keep it to preferences that change what an answer looks
like — and short enough to be worth opening every time.
