# Oculus course directory

This file describes a course folder in an Oculus library — one University of
Melbourne subject, synced from Canvas, Ed Discussion and Echo360. The folder
is named for the subject: `COMP30026_2026_SM2` is COMP30026, semester 2, 2026.
`syllabus.md` and `home.md` name it in full. If you are reading this from the
library's own `agents/` folder instead — where the in-app chat runs you —
the course folders are at `../courses/<CODE>/`, and everything below is about
them.

Oculus fills this folder by syncing Canvas, Ed Discussion and Echo360 from the
desktop app. Nothing in it is written by hand.

```
./
  syllabus.md      home.md
  announcements/   Canvas announcements, one .md each
  assignments/     briefs and due dates, one .md each
  ed/              Ed Discussion threads, NNNN-slug.md
  files/           downloads plus parsed siblings:
                     13.pdf  13.md  13.pages.json  13_images/
  modules/         module pages, in course order
  pages/           Canvas pages
  quizzes/         worksheets and quizzes
  images/          images referenced by the markdown above
  agents/          yours: INSTRUCTIONS.md, and memories/ linked to the
                   library's store (see Memory)
```

Per-page PDF text is **not** on disk — it lives in the Oculus database. Plain
`grep`/`rg` over this folder silently misses every slide deck; `oculus grep`
reads both halves.

## Rules

- Write only inside `agents/`. Everything else here is regenerated by sync, so
  edits elsewhere are both off-limits and lost.
- Keep memories as markdown in the library's memory store, not `.claude/` and
  not `.codex/`, so every agent that works here shares one. See Memory below:
  it lives under the library's own `agents/` because the in-app chat runs
  sandboxed and that is the only folder it can write to.
- Never touch `oculus.db` directly. The CLI is the door in both directions:
  `oculus search|grep|read|files|calendar` read it, and `oculus project` /
  `oculus task` write the student's plan into it — the same rows the app draws
  its board from, so a task you add appears there, on a board or in the Tasks
  view if it is filed nowhere.

## Memory

Write these as you finish a piece of work, not at the end of a session.

- `../../agents/memories/<CODE>/` — facts about **this subject**, where
  `<CODE>` is this folder's name. `agents/memories/` here is a symlink to it,
  so either path reaches the same files; prefer the one above, since it is the
  one the in-app chat can write.
- `../../agents/memories/` — facts that hold **across subjects**: how I work,
  what I am carrying this semester.
- `../../agents/TASTE.md` — **standing preferences**, as instructions, one
  bullet under `Writing`, `Working` or `Study`. Something said twice or stated
  as a rule; a single request is not.

One fact per file, named for the fact:

```markdown
---
name: info30006-assessment-emphasis
description: One line — what a reader sees before deciding to open this.
metadata:
  type: user | feedback | project | reference
---

The fact. For `feedback` and `project`, then **Why:** and **How to apply:**.
```

Link related files with `[[name]]`, and add one line to that folder's
`MEMORY.md` — `- [Title](file-name.md) — hook` — since the index is read
first.

Write what a session established and the library does not say. Not what sync
put on disk, or what one `oculus grep` would answer. Update the file that
already covers it rather than adding a second, and delete one that turns out
wrong: this is a store of what is true, not a log.

`TASTE.md` and the global bucket are what the in-app chat is pointed at first
on every conversation, so keep them short.

## Tools

Bash, `grep`, `find` and other read-only tools are fine. The `oculus` CLI is
the better door for anything indexed — if it is not on `PATH`, ask me to
install it (`bun run cli:install` in the Oculus repo) rather than working
around it.

```bash
oculus search "kkt conditions" -s COMP30026 -n 8  # rank pages by meaning
oculus grep "sprint retrospective" -s COMP30026   # regex over markdown AND pdf pages
oculus read 13.pdf --pages 30-35                  # parsed page markdown
oculus files COMP30026 --type pdf                 # what is there to read
oculus calendar COMP30026 -d 14                   # classes and due dates
oculus project list -s COMP30026                  # what is planned, and how far along
oculus task add -p 3 --batch -                    # a whole breakdown in one call
oculus task add "email the tutor"                 # no -p: filed nowhere, for now
oculus task list                                  # every task, unfiled ones first
oculus task refile 12 -p 3                        # file it, subtasks and all
```

Planning is a write, so it has its own rules. A project's board names its own
columns (`oculus project show <ID>` prints their ids), and a breakdown goes in
as one `--batch` JSON array rather than one command per task —
`oculus task add --help` is the contract. A task **need not belong to a
project**: `oculus task add` with no `-p` writes an *unfiled* task, which is
what to reach for when something has to be written down before anyone has
decided where it goes. `oculus task refile` files it later and takes its
subtasks with it. Do not invent an "Inbox" project for this; there is nothing
to clean up if an unfiled task is never filed.

Pass this folder's own subject code to `-s`: the CLI has no notion of the
working directory, so without it you get the whole library back. `search`
embeds the query through the embedding provider configured in the app, so it
needs that key to be set; when it can't run it fails loudly and points at
`grep`. Add `--json` to any command for machine-readable output.
